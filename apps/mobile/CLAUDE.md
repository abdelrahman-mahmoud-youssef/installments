# Mobile app (Expo + React Native + TypeScript)

iOS-first companion app for the installment SaaS. Shared codebase for iOS and Android via Expo SDK 57 + Expo Router.

## Run

- `pnpm dev:mobile` from the repo root (backend must be running on port 3001); root `pnpm dev` intentionally does not start the mobile app
- The API URL is auto-derived from the Expo dev server host (phone on the same LAN hits `http://<dev-machine>:3001`). Override with `EXPO_PUBLIC_API_URL`.
- Auth is a JWT from `POST /auth/login`, stored in `expo-secure-store` and sent as a Bearer header (no cookies — the web proxy is not used).

## Building for iOS (EAS)

- No Mac/Xcode needed — `eas build --profile preview --platform ios` (internal test install) or `--profile production` (App Store) build in the cloud, per `eas.json`.
- Both non-dev profiles set `EXPO_PUBLIC_API_URL` to a real deployed backend — update the placeholder in `eas.json` once the backend is live (the mobile app hits it directly, so it must be **publicly** reachable, unlike the web frontend's Railway-private backend URL).
- `app.json`'s `icon`/`adaptiveIcon`/splash assets live in `assets/`, generated from the same master logo (`apps/frontend/public/qistak.png`) used for the web app's PWA icons — regenerate from that file if the brand mark changes, don't hand-edit the PNGs.
- `eas submit --platform ios` uploads to App Store Connect once Apple Developer credentials are set up via `eas credentials`.

## Architecture (do not silently change)

- **Routes** live in `app/` (Expo Router file-based). Five tabs — Dashboard `(home)`, Contracts, Customers, Wallets (payment methods), More — rendered by `NativeTabs` (`expo-router/unstable-native-tabs`, SF Symbols on iOS, Ionicons on Android). Each tab is a folder with a `_layout.tsx` re-exporting `TabStack` (`src/navigation/tab-stack.tsx`) and an `index.tsx`, so every tab root gets a native large-title header; the tab screen sets its title via `<Stack.Screen options>` (Customers also puts its search in `headerSearchBarOptions`). The Wallets tab switches between wallets and money contacts (counterparties) with a `SegmentedControl`; the header search filters wallets locally and contacts server-side. Create flows: `contract/new` (from the Contracts tab, the dashboard header "+" and a customer's page, with inline customer creation) and the customer form sheet (from the Customers tab). Detail screens (`contract/[id]`, `contract/new`, `customer/[id]`, `wallet/[id]`, `contact/[id]`, `payment-claims`, `reports`, `staff`, `activity`, `offers`, `shop`, `settings`, `support`, `announcements`, `new-announcement`, `notifications`, `security`) stay in the root stack, reached from the More tab (admin-only: `staff`, `activity`, `offers`, `shop`, `notifications`; all roles: `payment-claims`, `reports`, `announcements` — only admins get the composer — `support` with an unseen-reply badge, `security`, `settings`); `login` and `register` are the only unauthenticated routes (`AuthGate` in `app/_layout.tsx`).
- **Floating actions** (primary create/record buttons) always go in `FloatingActionBar`, which uses the native safe area so the button clears the iOS tab bar; never position a floating button with `useSafeAreaInsets` by hand.
- **Brand theming**: `colors.primary`/`primaryMuted`/`onPrimary` follow the tenant's shop brand color (`user.tenant.brandColor` from `/auth/me`, palettes in `src/theme/brand-palettes.ts`), synced into `ThemeProvider` by `AuthProvider` and persisted so the app boots in the right color. Everything else in `tokens.ts` stays semantic (success stays green even for a rose brand). All header options come from `useStackScreenOptions()` — never set `headerStyle`/`headerBlurEffect` per screen.
- **Navigation chrome is native and system-styled** (Liquid Glass on iOS 26, material on older iOS, Material on Android): headers are transparent on iOS and every root `ScrollView`/`FlatList` must pass `contentInsetAdjustmentBehavior="automatic"` so content scrolls beneath the header and tab bar.
- **Theme**: all colors/spacing/radius/font sizes come from `src/theme/tokens.ts` via `useTheme()`. Never hardcode a color in a screen. Light/dark/system mode and the font-size setting live in `theme-context.tsx`; every text size flows through `fontSize(token)` so the font-size setting scales the whole app.
- **LTR content in RTL**: phones, emails, account numbers, codes and URLs shown inside Arabic text are wrapped with `isolateLtr()` (`src/lib/format.ts`) so bidi reordering can't scramble them; never put isolates inside a `tel:`/`wa.me` URL. `TextField` auto-forces LTR typing for email/url/phone keyboards (`ltr` prop for other cases like the slug).
- **Haptics**: selection controls (SegmentedControl, ChoiceChips, FilterChips, OptionTiles) fire `selectionHaptic()` and toasts fire `notificationHaptic()` from `src/lib/haptics.ts`; reuse these instead of calling expo-haptics directly.
- **Arabic typeface**: the user picks Cairo/Tajawal/Almarai/system in Settings (`src/theme/arabic-fonts.ts`); `AppText` applies it automatically in Arabic, so never set `fontFamily` on text directly (the monospace token is the one exception).
- **i18n**: every string goes through `useI18n().t('section.key')` with dictionaries in `src/i18n/translations.ts` (en + ar, structurally identical — `ar` is typed as `typeof en`). Arabic switches the app to RTL via `I18nManager.forceRTL` + reload; layouts must use logical properties (`start`/`end`, `flexDirection: 'row'`) so they flip automatically. Startup only persists the direction (applied on next launch) and never reloads: a programmatic reload in Expo Go comes back without Expo's native modules. Expo Go also resets RTL to the device language on every launch, so test Arabic RTL there with the phone set to Arabic, or use a development build. Native chrome does not follow `forceRTL` (iOS resolves it from the app bundle's language), so `NativeTabs` gets an explicit `direction`, and `isRTL` comes from `I18nManager.isRTL` (the real layout direction), not the locale. React Native swaps `textAlign` `left`/`right` under RTL, so text alignment always goes through `logicalTextAlign.start`/`.end` (`tokens.ts`); `AppText` defaults to start because unaligned text would follow the app bundle's language (LTR) instead.
- **API layer**: all HTTP through `src/api/*` (thin typed wrappers over `src/api/client.ts`). Never `fetch` in a component. Money stays in minor units end-to-end; formatting only via `formatMoney`/`MoneyText`.
- **Server state**: TanStack Query hooks in `src/hooks/queries.ts` (infinite queries for paginated lists, mutations invalidate related keys). UI state is local React state.
- **UI primitives** in `src/components/ui/` (AppText, Card, Button, Badge, TextField, BottomSheet, ConfirmSheet, Skeleton, EmptyState, ErrorState, toast…). Feature components in `src/components/<feature>/`. Reuse these; never re-implement a card/sheet/badge inline.
- **Glass is for the floating layer only.** `GlassSurface` (`expo-glass-effect`, solid `surface` fallback where Liquid Glass is unavailable) backs `BottomSheet`, the toast, and `Button variant="glass"` (floating primary actions such as "Record payment"). Content — `Card`, list rows, stat tiles — stays opaque; never put glass on scrolling content.
- **OVERDUE is derived** on the client the same way as the backend: `dueDate < today AND status IN (PENDING, PARTIALLY_PAID)` (`src/lib/statuses.ts`).
- Destructive actions (remove wallet, deactivate, sign out) always go through `ConfirmSheet`.
